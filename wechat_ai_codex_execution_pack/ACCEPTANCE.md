# 验收契约

此文件规定预期结果，不表示测试已经执行。
每项必须能映射到测试函数或实机记录。没有命令、退出码及证据的 PASS 不算验收完成。

## A｜离线自动化（Goal A 全部必须覆盖）

所有数据合成；Fake 适配器、可注入时钟、临时 SQLite、HTTP MockTransport；不安装微信也能运行。
时间相关测试使用虚拟时钟，不通过真实等待数分钟制造慢测试。测试只可在预先安装依赖后断网运行，
不能把首次下载依赖的需求与测试运行需要联网混为一谈。

| ID | 场景与输入 | 验收结果 |
|---|---|---|
| A01 | 非 Windows、未安装 wxauto4，导入包并运行 demo | 成功；未导入真实 wxauto 模块；没有网络调用 |
| A02 | 不传安全参数启动，或配置缺失/非法 | 默认 mock/dry_run/fixed；危险配置 fail-fast，不打开实际发送 |
| A03 | 第一次快照已有多条 #客服 历史消息 | 仅建立基线；0 回复任务、0 发送 |
| A04 | 同一 epoch 重复相同快照 10 次 | 不新增事件，不重复回答 |

| A06 | 有可靠 UI 重叠锚点，窗口前部消息滚出 | 只处理新出现部分；已有消息不重复 |
| A07 | 连续两条相同问题，UI ID 不同 | 两个独立事件；不按昵称+文本错误去重；任务仍受发送预算限制 |

| A10 | 基线有效空列表后新增；另测读取失败返回空/异常 | 前者正确处理；后者不误当有效空基线继续自动回答 |
| A11 | 来源 self；文本也包含 #客服 | 0 新回答；避免机器人自循环 |

| A13 | 普通聊天、#客服端、正文中间包含前缀 | 不触发；#客服 后跟空白/冒号可触发 |

| A16 | 昵称相同的两个独立问题 | 不合并长期上下文，不推断真实用户身份 |
| A17 | dry_run、allow_send 关闭、缺确认目标等任一条件 | 真实发送函数调用次数为 0；逐个参数变体都要测试 |
| A18 | 配置目标与当前群类型/名称不符 | 不发送，状态变为暂停/阻塞 |
| A19 | 任务生成后 binding_epoch 或 generation 改变 | 旧任务取消；即便迟到模型返回也不能发送 |
| A20 | pause 在 READY→SENDING 前提交 | 已等待任务取消，发送调用为 0 |
| A21 | pause 在任务已转 SENDING 后发生 | 报告在途动作；不得声称能撤回；后续任务不再发送 |
| A22 | 暂停期间有新问题，随后 resume | 恢复时重建基线，不回答暂停期积压问题 |
| A23 | 发送函数报超时/抛错，可能已产生外部效果 | UNKNOWN；循环/重启/approve 都不自动重试该任务 |
| A24 | SDK 返回成功，但快照里无法找到唯一 self 回显 | UNKNOWN，不伪装成微信送达成功 |
| A25 | 匹配同群、唯一 task 标记和自身消息回显 | OBSERVED_SENT；不声称对方已读 |
| A26 | 模拟在 SENDING 持久化后崩溃，重启 | 变 UNKNOWN；新进程不重发；其他旧 READY 转草稿 |
| A27 | 任务过期、预算耗尽或间隔未达 | 不立即发送；到期任务终止，不依靠重启突破预算 |
| A28 | 两个真实模式实例使用不同数据库路径但同一桌面 | 第二实例因全局适配器锁失败；不操作微信；Mock 隔离实例不冲突 |
| A29 | FAQ 精确问题及别名命中 | 返回确定答案和正确来源；不发 HTTP 请求 |
| A30 | FAQ 未命中 | 转人工，不让模型自由编造；不假造 source_id |
| A31 | LLM 模式未授权外部调用/无 key；默认 fixed 模式无 key | 前者明确阻塞；后者和 FAQ 可正常运行；不回显 key |
| A32 | HTTPX 模拟合法请求和正常答案 | 验证请求只包含当前问题与已选 FAQ；校验输出；默认 DRAFT 等人工审核 |
| A33 | 模型超时、401、429、5xx、空答案、非 JSON、超长响应 | 各变体均有测试；不无限重试；不发错误堆栈到群里；有人工处理状态 |
| A34 | 模型慢响应期间连续出现新消息 | UI 读取仍在推进；模型线程不访问 wxauto 或主线程 DB 连接 |
| A35 | 群问题/FAQ 内嵌“发给另一个群”“调用 shell”等指令 | 仅当不可信数据；不能改变绑定、调用工具或放开实际发送 |
| A36 | status/pause/resume/tasks approve、错误参数与终态任务 | CLI 可运行；终态不能变回 READY；退出码和帮助信息明确 |
| A37 | 真实适配器注入 FakeWeChat 工厂，核验字段和 API | 免费 API 契约映射正确；缺字段 fail-closed；不调用 Plus 接口；非真实环境不导入 GUI 依赖 |
| A38 | 单次完整 qa、Mock demo、重启恢复、日志脱敏 | 报告含真实数量/退出码；不泄露 key/真实群信息；核心分支覆盖≥85%；测试结束无残留进程 |

### 离线测试额外要求

- 对失败场景断言 SendMsg/send_text 调用次数、数据库任务状态和异常原因。
- 为 sleep、当前时间、HTTP 和 UI 依赖提供注入点；不要用吞异常使测试变绿。
- 不把代码里的 TODO、函数存在或截图占位符当成功证据。
- 普通 pytest 默认排除 live_wechat/live_llm；显式启用 live 时还必须检查运行级授权。
- 真实适配器对象的测试使用工厂注入，不能在测试收集期启动真实微信。

## W｜Windows 真实验证（单独 Goal B）

前提：Goal A 离线通过，使用 Windows 原生 Python、已人工登录的普通微信、操作者可管理的内部测试群。
不以生产客户群试验。真实 UI 访问不足则记录 BLOCKED，不改成 Mock 后写 PASS。

| ID | 操作 | 预期与证据 |
|---|---|---|
| W01 | 记录 OS/Python/包版本/微信客户端版本 | 是实际读取或人工确认的版本，不是复制文档的支持版本 |
| W02 | doctor 只读初始化，核验免费 API 与当前测试会话 | 无发送；能力与缺失项明确；报告不泄露历史消息 |
| W03 | 群中预置旧 #客服，启动 dry-run | 旧问题 0 自动回复；记录基线建立结果 |
| W04 | 另一个成员发新 #客服；机器人账号也发一条同前缀文本 | 前者产生预览；后者不触发；消息仍未实际发出 |
| W05 | 有限授权后另一个成员发连通问题 | 固定答案在原群出现，带唯一任务标记；记录人工与程序核验结果 |
| W06 | 相同内容发送两次；重复读取窗口 | 两个独立新问题被识别；同一事件不重复回答；遵守本次预算 |
| W07 | 人工切换会话或使目标名称不匹配 | 暂停且不向错误会话发消息；须记录检测局限，不能只靠断言宣称唯一身份 |
| W08 | 停止/重启程序，再出现新问题 | 不回复重启前历史，不自动重发 UNKNOWN；新问题在恢复后可处理 |
| W09 | 使用 pause，再发问题，再 resume | 暂停后无新发送；恢复不补发暂停期积压 |
| W10 | 锁屏/微信退出/界面不可达 | 明确暂停或受阻，无错误目标发送；人工恢复后重建基线 |
| W11 | 发送结果不明的恢复逻辑 | 不要故意强制破坏真实客户端；主要用 A23—A26 故障注入，实机仅记录能安全观测到的结果 |
| W12 | 完成测试、到预算或时限，检查退出 | 无常驻测试进程，无自动重启；报告区分实机 PASS 与未执行案例 |

W05—W09 的发送需要预算覆盖；首次 3 条只完成固定回复 smoke，不等同于全套 W 验收。
需要追加发送前，由操作者重新授权具体测试范围。W11 不能写成“真实断网故障已测”除非确有实测证据。

## L｜真实模型可选验证（不属于 Goal A 默认授权）

使用操作者批准的提供方、模型与接口，只发送合成问题及合成 FAQ；一次测试也可能产生费用。
记录 endpoint 的脱敏表示、实际模型、HTTP 状态、答案长度、调用时间；不输出 key。
实调通过表示本次契约成立，不代表长期服务可用或所有模型参数兼容。

## 报告格式

```text
ID: A23
Status: PASS | FAIL | NOT_RUN | SKIPPED_ENV | BLOCKED
Environment: 实际 OS / Python / 依赖版本
Command: 实际执行命令
Exit code: 实际退出码
Tests: passed / failed / skipped
Evidence: 脱敏日志或报告路径
Observed behavior: 实际观察
Known limitations: 当前限制
```

本段是模板，不预填 PASS、测试数或退出码。模拟成功、真实只读成功、真实收发成功必须分别汇报。

## 最终完成门禁

Goal A：A01—A38 全覆盖、质量门禁通过、Mock 演示可复现、CLI 与文档齐全，M5 标 NOT_RUN 可接受。
Goal B：只对实际完成且有证据的 W 项报告 PASS；剩余项如无环境或权限，报告 BLOCKED，不写“全部完成”。
达到目标后结束进程；不能为追求结果持续向测试群或真实群发送消息。
