# Codex 项目执行约束

## 先读

依次阅读 `GOAL.md`、`PLAN.md`、`ACCEPTANCE.md`、`config.example.toml`、`REFERENCES.md`。
本包是待实施规格，不是已完成的软件。不要把模板状态、期望输出或本文件中的命令当成实际运行结果。
已有仓库的上级指令仍适用；保留用户现有文件，不覆盖已有配置和无关代码。

## 本次唯一产品目标

开发普通微信群 AI 客服的 v0.1 试验程序：一个普通微信客服账号、一个人工指定的测试群，
Python 3.11 + wxauto4 免费版 + SQLite，通过 `#客服 问题` 触发文本回答。
先交付离线可测试程序，再验证 Windows 真实收发。不要迁移企业微信，不要开发 Java/TS 后端。

## 范围与依赖

- 单机、单进程、模块化；UI 操作集中在创建微信实例的同一线程。
- 首版命令行操作；不开发 Web 前端、FastAPI、Dify、Redis、Celery、消息中间件或向量数据库。
- 核心优先标准库；HTTP 使用 HTTPX，跨进程互斥使用 filelock；测试使用 pytest、pytest-cov、Ruff。
- wxauto4 作为 Windows 可选依赖，延迟导入。Mock 开发不得要求安装微信、Windows 扩展或模型密钥。
- 禁止依赖 wxautox4、Plus 激活及其专属 API，包括 AddListenChat、StartListening、GetNextNewMessage、
  GetSubWindow、GetHistoryMessage、IsOnline、GetMyInfo、KeepRunning，以及 Plus 的消息 hash。
- 阅读开发当时的项目文档并核验实际已安装版本。不同版本签名不一致时记录差异，不编造接口。
- 不自动下载不明来源的旧微信安装包，不修改注册表/更新策略，不关闭系统安全措施或绕过授权。

## 必须保持的行为

1. 默认 `adapter=mock`、`send_mode=dry_run`、`reply_engine=fixed`；实际发送和外部 LLM 调用分别显式授权。
2. 自动化单元/集成测试不操作真实微信、不访问真实模型；只用合成群消息和 HTTP MockTransport。
3. 真实运行只允许人工确认的一个测试群。群成员只是显示名，不作为身份认证信息。
4. 启动先建立历史基线，不回答历史消息。UI ID 仅在当前绑定 epoch 内辅助定位，不当作永久微信消息 ID。
5. 两条不同 UI ID 的相同文本是两条消息；不可用 sender+content 作为全局去重键。
6. 失去窗口锚点、群名/类型异常、UI 重建或身份不明时，取消旧待发任务并暂停，不猜测新旧消息。
7. 消息入库及任务状态先持久化，再做下一步。LLM 线程不访问 wxauto，也不共用主线程 SQLite 连接。
8. 模型只产生草稿；不决定目标群、发送开关，不运行 shell、工具调用、业务写操作或管理命令。
9. `dry_run` 不调用真实发送函数。发送异常/结果不明设为 UNKNOWN，不自动再次发送。
10. 人工暂停取消未开始任务；恢复不发送暂停期间积压或启动前历史问题。已经进入发送动作的任务可能无法撤回，必须显示出来。
11. 禁止通过昵称匹配忽略自身消息；优先使用经过验证的来源属性。不能确认来源时忽略。
12. 私密信息、密钥、全量群聊、屏幕截图不进入公开仓库、测试报告或外部模型。

## 执行方式

先检查工作区、解释器、依赖与既有测试，再按 M0→M4 实现。每个阶段：编写验收用例、实现、运行、修复、记录。
可以自主决定不影响验收条件的文件组织细节，并记录在 `reports/DECISIONS.md`。
不要每个小步骤都等待确认；不得擅自扩大范围、购买服务、发送真实微信消息或改变用户系统配置。
代码缺陷应继续修复；缺少 Windows/微信/人工授权只阻塞对应实机步骤，不能阻塞 Mock 开发。
连续遇到同一个外部环境阻塞时，保存证据并暂停该阶段，不用无限重试伪装进展。

## 质量门禁

按 `ACCEPTANCE.md` 实现全部离线核心测试。必须运行格式、静态检查、pytest、Mock 演示及重启恢复测试。
核心业务模块分支覆盖率目标为 85%，且关键安全场景必须逐条通过；覆盖率不能替代场景验收。
不得删测试、降低阈值、无理由 skip/xfail 或把真实渠道偷偷替换成 Mock 来制造通过结果。
异常测试应断言数据库状态和适配器调用次数，不只验证函数不报错。

## 实机权限

Goal A 不得初始化或操作真实微信。Goal B 默认只读；发送需要操作者指定测试群和本次有限发送授权。
登录、验证码、群成员告知以及具体会话是否可测试，由操作者处理。无法访问当前桌面时输出阻塞，不绕过沙箱。
没有真实 Windows 执行证据，Windows 验收只能标注 NOT_RUN、BLOCKED 或 SKIPPED_ENV，不能标记 PASS。
真实发送测试不能使用生产客户群，不能自行把 max_sends 或发送范围调大。

## 每阶段交付与停止条件

更新 `reports/PROGRESS.md`：阶段、改动、运行命令、退出码、测试数、失败/跳过原因、剩余工作。
最终更新 `reports/ACCEPTANCE_REPORT.md`：逐项结果及日志路径，明确区分代码完成、Mock 通过、Windows 只读通过、Windows 收发通过、LLM 实调通过。
不要提交 API key、真实数据库、聊天内容或截图；不要自动 push、部署、定时启动或持续运行客服进程。
达成当前 Goal 后停止；外部阻塞时记录可复现信息和操作者所需动作后停止对应阶段。
